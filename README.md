# marketplace-payment-service
Agile project: billing and payment gateway for a marketplace







пз 1

Лабораторная работа посвящена этапу инициализации и Agile-планирования сквозного проекта программной системы по методологии Scrum. Задание включает формирование продуктового бэклога (Product Backlog), разработку пользовательских историй (User Stories) по стандарту INVEST с критериями приемки в BDD-нотации, формализацию регламентов качества (DoD и DoR), оценку трудоемкости задач в Story Points и настройку интерактивной Agile-доски первого рабочего спринта.

### Лабораторная работа № 1. Планирование проекта Agile

#### Задача

Целью данной работы является освоение базовых принципов Agile-подхода к разработке программного обеспечения и формирование практических навыков инициализации и итерационного планирования проекта по методологии Scrum/Kanban. Необходимо выполнить декомпозицию предметной области, составить иерархический бэклог продукта (Product Backlog), разработать формальные стандарты качества (DoD и DoR), сформулировать пользовательские истории (User Stories) с критериями приемки в нотации BDD (Acceptance Criteria), провести оценку относительной трудоемкости в Story Points и сформировать план первого рабочего спринта (Sprint 1) на Agile-доске.

#### Варианты выполнения задания

Работа является первым этапом сквозного проекта, развиваемого на протяжении всех 8 лабораторных работ. Студент выбирает один из предложенных вариантов программной системы.



Вариант и тематика проекта: Специфика бизнес-правил:
Вариант 1: Сервис биллинга и платежного шлюза маркетплейса



Ключевые эпики (Epics):
- Интеграция с внешними банковскими API
- Обработка транзакций и холдирование
- Формирование фискальных чеков и возвраты



Целевой инкремент Спринта 1:
Инициализация платежной сессии, валидация реквизитов, обработка Callback-уведомлений банка.



Специфика бизнес-правил:
Идемпотентность транзакций, таймауты внешних шлюзов, безопасность передачи данных.


#### Технические требования

**Инструментарий:** Облачные платформы управления проектами без локального администрирования — **GitHub Projects** (рекомендуется для прямой связки с Git и CI/CD в следующих работах), **YouTrack Cloud** или **Trello**.

**Этап 1. Формирование Product Backlog и критериев качества:**

- Создайте проект на выбранной облачной платформе и выделите не менее **3 глобальных Эпиков (Epics)** для предметной области выбранного варианта.
- Сформулируйте не менее **6 пользовательских историй (User Stories)**, распределенных по эпикам, строго соблюдая шаблон: `«Как [роль / актор], я хочу [действие / функционал], чтобы [бизнес-ценность / результат]»`.
- Проверьте соответствие сформированных историй критериям **INVEST** (Independent, Negotiable, Valuable, Estimable, Small, Testable).
- Для каждой истории составьте критерии приемки (**Acceptance Criteria**) в BDD-формате: `Given [исходный контекст/предусловие] → When [действие пользователя/системы] → Then [ожидаемый результат/состояние]`.
- Сформулируйте и зафиксируйте стандарты команды: регламент готовности к разработке **Definition of Ready (DoR)** и регламент готовности релиза **Definition of Done (DoD)**.

**Этап 2. Оценка трудоемкости и планирование Спринта 1 (Sprint Planning):**

- Проведите относительную оценку User Stories в **Story Points (SP)** по модифицированной шкале Фибоначчи (1, 2, 3, 5, 8, 13) и обоснуйте полученные значения.
- Сформулируйте цель первого спринта (**Sprint Goal**) с плановой емкостью команды 15–20 Story Points на 2 недели.
- Перенесите отобранные истории в **Sprint Backlog** и выполните их инженерную декомпозицию на атомарные технические подзадачи (Sub-tasks трудоемкостью 1–4 часа):
  - `[Backend / Domain]` — проектирование структур данных и логики сервиса;
  - `[Documentation]` — описание контрактов API и комментирование интерфейсов;
  - `[Testing]` — разработка Unit-тестов и Mock-объектов;
  - `[DevOps / Integration]` — настройка правил слияния веток и проверок сборки.

**Этап 3. Конфигурация интерактивной Agile-доски (Sprint Board):**

- Настройте колонки жизненного цикла задач: `Product Backlog` → `Sprint Backlog (To Do)` → `In Progress` → `Code Review / PR` → `Testing / QA` → `Done`.
- Назначьте метки (Labels: тип задачи, приоритет, оценка SP, исполнитель) и свяжите технические подзадачи с родительскими User Stories.

#### Отчетность

Отчет по лабораторной работе оформляется и предоставляется в виде отдельного файла в формате **PDF** в соответствии с требованиями Порядка подготовки, выполнения, оформления и защиты лабораторных работ от 05.07.2013.

В тексте отчета в обязательном порядке приводится **активная рабочая гиперссылка на проект** (интерактивную Agile-доску в GitHub Projects / YouTrack / Trello), а также следующие структурированные разделы и материалы:

- Титульный лист, цель работы и краткое описание предметной области выбранного варианта;
- Формальные регламенты команды Definition of Ready (DoR) и Definition of Done (DoD);
- Спецификация требований: перечень User Stories с оценками в Story Points и BDD-критериями приемки (Given–When–Then);
- Дерево инженерной декомпозиции задач первого спринта с категориями, исполнителями и трудоемкостью в часах;
- Формулировка цели спринта (Sprint Goal), обоснование оценок сложности и обзорные скриншоты настроенной Agile-доски со всеми колонками.

**Примечание:** Сформированные в данной работе User Stories, технические подзадачи и регламенты DoD/DoR являются базисом для последующих лабораторных работ сквозного цикла.
